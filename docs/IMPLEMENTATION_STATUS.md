## Task 02 evidence and limits

The transport core now validates bounded SDP/ICE inputs, orders trickle candidates around remote-description setup, tracks connection and reconnect transitions, converts monotonic capture time to the 90 kHz RTP video timebase, bounds encoded-frame queue bytes/count, requests a keyframe after overflow, and produces a timestamped synthetic I420 color-bar source for an encoder adapter. `WebRtcEnginePort` exposes asynchronous control and metadata events only; its Flutter implementation is pinned in `pubspec.lock` and emits SDP/ICE/connection/track metadata with no capture or media-pixel API.

The Rust tests use synthetic values and do not instantiate libwebrtc, encode H.264, open sockets, authenticate peers, or render video. A real H.264 stream, DTLS-SRTP, signaling, native platform adapters and hardware verification remain open. See [Task 02](../codex/02-transport-spike.md), [ADR-0002](adr/0002-transport-spike.md), and the [transport implementation and deferred-test report](spikes/transport-experiment-blocker.md).
